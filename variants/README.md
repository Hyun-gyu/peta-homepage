# 홈페이지 디자인 후보 (2026-07-24)

배포본이 아니다. 상위 폴더의 `index.html` / `styles.css`는 그대로이고,
이 폴더의 파일들은 그 위에 **덮어쓰기 방식**으로 얹혀 후보안을 만든다.
어느 것도 `peta-homepage-static.zip`에 들어가 있지 않다.

## 보는 방법

저장소 루트를 웹서버 루트로 띄운 뒤 아래 경로를 연다.

```bash
cd <이 저장소 폴더>
python3 -m http.server 8787 --bind 127.0.0.1
```

| 후보 | 경로 |
|---|---|
| 현재 배포 예정본 | `http://127.0.0.1:8787/` |
| 평평한 스타일만 | `http://127.0.0.1:8787/variants/modern.html` |
| + 구조 개편 | `http://127.0.0.1:8787/variants/v2.html` |
| **+ 조용한 히어로 (유력 후보)** | `http://127.0.0.1:8787/variants/v3.html` |

iCloud 폴더 권한 때문에 서버가 안 뜨면, 폴더를 로컬 디스크로 복사한 뒤 띄운다.

## 각 후보가 무엇인가

세 후보는 누적된다. v3 = modern + v2 + v3.

### modern.html — 평평한 스타일

`opencode.ai`의 DESIGN.md에서 가져온 방향. 그림자를 전부 없애고 카드의 흰 배경도
걷어서, 카드가 떠 있는 대신 얇은 선으로만 그려진 윤곽이 된다. 섹션마다 배경색이
번갈아 나오던 것도 없애 한 장의 캔버스로 이었다. 영문 라벨은 고정폭 글꼴.

**모서리는 일부러 원래대로 뒀다.** opencode는 4px까지 조이지만, 페타는 격자 배경과
넓은 여백을 쓰는 도면 쪽 인상이라 둥근 모서리가 더 맞는다는 판단.

**한글은 Pretendard 유지.** opencode처럼 전부 고정폭으로 가면 한글 글자가 없는
서체라 깨진다. 영문 라벨만 고정폭으로 분리했다.

파일: `modern.css`

### v2.html — 구조 개편

- Industries 섹션 삭제. 각 솔루션 카드 아래 "적용 산업" 한 줄로 흡수.
- Proof 스트립을 히어로 다음 → 프로젝트 다음으로 이동. 변명이 아니라 증거로 읽히게.
- Why 카드 5장 → 3장. 나머지 둘은 도입 방식 섹션과 내용이 겹쳤다.
- 섹션 제목을 이름표에서 주장문으로. ("현장 기반 산업 AI 프로젝트" → "지금 두 곳의
  현장에서 실제 데이터로 검증하고 있습니다.")
- 솔루션 카드 요약문을 구체화. CAD 카드는 히어로 대시보드에 이미 있던
  `가로 길이 100mm 늘려줘` 예시를 본문으로 끌어왔다. 새로 공개한 정보는 없다.
- Pain Points 유지 + 보강. 명사 나열에서 실제 장면으로. ("그 사람이 자리를 비우면
  일이 멈춥니다")
- 히어로 배지 줄 삭제. 같은 세 역량이 제목·부제·배지·캐러셀 버튼에 네 번 나왔다.
- 히어로 부제를 역량 나열에서 고객의 첫 두 질문에 대한 답으로 교체.

파일: `v2.css`, `siteContentV2.js`, `appV2.js`

### v3.html — 조용한 히어로 (유력 후보)

- 히어로를 텍스트만 남긴 단일 컬럼으로. 높이 538px.
- 배경에 U자 브라켓 정면도를 치수선과 함께 옅게(14%) 까는 SVG 선화. 사진이 아니라
  선화인 이유는 44px 격자 배경·오프화이트 캔버스와 싸우지 않기 위해서.
- 대시보드 패널을 히어로에서 빼서 Pain Points 다음 `How it works` 섹션으로 이동.
  폭이 600px → 1180px로 늘어 내부 코드와 파라미터 표가 읽힌다.
- 서사 순서가 생긴다: 문제 → 같은 데이터가 판단으로 바뀜 → 솔루션 상세.

파일: `v3.css`

**열린 쟁점:** 첫 화면에 증거가 없다. 패널이 1388px 지점(두 번째 화면)이라,
5초 만에 이탈하는 방문자는 텍스트만 본다. Pain Points를 압축해 패널을 첫 스크롤
안으로 끌어올릴지 미결.
